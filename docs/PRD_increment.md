# 水质检测仪助手 — 增量 PRD（简单 PRD）

> 本文档只描述**相对已交付第一版的变更部分**，作为 `docs/PRD.md`（全量）的增量补充，供架构师与开发按增量实现。基线现状见「当前应用现状」一节（以实际代码为准）。

## 0. 变更基线（当前应用现状）

- 技术栈：Flutter/Dart 单代码库，蓝白 `#1976D2`/`#E3F2FD`，Android + Windows 响应式。
- 导航壳 `lib/pages/shell_page.dart`：现为 **5 个**目的地（首页 / 图片转Excel / 大肠杆菌计算 / 设置 / 国标验证），手机底部导航 + 桌面侧边 Rail；首页为正方形功能格。
- 图片转Excel：`image_to_excel_page.dart` + `image_to_excel_provider.dart`，现有「仪器类型选择（MCGS/E.co）」；OCR `lib/services/ocr_service.dart`（桌面 = 本地 Python(PaddleOCR) 子进程 `LocalPythonOcrService`；移动端/云端 = `CloudOcrService` HTTP）；Excel 导出 `excel_service.dart`。
- 大肠杆菌计算：`calculation_page.dart` + `calculation_provider`（吸光度拟合 A/B/R²），**当前依赖「先在图片转Excel页识别数据」**。
- 国标验证：`pages/verification/*`（工作空间列表/详情/结果），`services/workspace_store.dart`（JSON 文件持久化，目录 = 应用文档目录/`workspaces/<id>.json`），模型 `models/workspace.dart`（Workspace > Dataset > Measurement；Workspace 含 `name/parameter/createdAt/datasets/results/overrideLimits`）。
- 数据传输：**服务层已实现**（`file_transfer_service.dart`、`discovery_service.dart`、`transfer_provider.dart`：HttpServer + UDP 发现 + 二维码协议 `WQA|1.0|{ip}:{port}|{token}`），但**无传输页面**（历史 bug）。
- 设置页 `settings_page.dart`：OCR 引擎本地/云端切换等。

## 1. 产品目标（增量）

1. **导航收敛与职责清晰**：从 5 tab 收敛为 3 tab（工作空间 / 工具 / 数据传输），补齐缺失的「数据传输」正式页面，修复历史导航 bug，让核心流程各归其位。
2. **工具链闭环到工作空间**：让「图片转Excel」「大肠杆菌计算」等子工具可独立采集数据，并在执行完成后一键「创建/导入到工作空间」，形成「采集 → 计算 → 归档」的完整闭环。
3. **工作空间成为一等公民**：工作空间从「国标验证专用容器」升级为全应用通用的项目管理容器，支持增删改查、回收站、字段化命名文件夹与多维度搜索排序。

## 2. 用户故事（增量）

1. 作为现场用户，我希望底部导航只有「工作空间 / 工具 / 数据传输」三个入口，打开应用默认进入「工具」页，这样我能一眼找到要用的工具、并按需切到数据传输。
2. 作为现场用户，我希望拍照时应用能在预览上给出「拍正表格」的引导（参考线/边缘提示），这样 OCR 识别的表格结构更准、更少返工。
3. 作为实验分析人员，我希望在图片转Excel里不用手动选择仪器类型，系统能识别出表格结构，并且我能「框选」需要的数据，这样我只要留下关心的列/区域即可。
4. 作为实验分析人员，我希望大肠杆菌计算页能独立拍照或导入数据，不再提示「请先在图片转Excel页识别或导入」，这样我能直接用该工具完成计算。
5. 作为实验分析人员，我希望任一子工具执行完成后都能把生成的文件自定义命名并保存/导入到某个工作空间，这样成果可被统一归档与复用。
6. 作为管理员，我希望工作空间支持增删改查、删除进回收站（30 天自动清理）、按合同编号/项目名称等字段命名文件夹，并能按创建时间正/逆排序、全文或按字段搜索，这样我能高效管理多个项目。

## 3. 需求池（增量，按优先级）

### P0（本次必须完成）

- **P0-1 导航重构为 3 tab**：`shell_page.dart` 目的地改为「工作空间 / 工具 / 数据传输」；默认选中「工具」；「工具」页内**不再展示「数据传输」入口**（数据传输独立为右 tab）。桌面端左侧 Rail、手机端底部导航同步调整。
- **P0-2 数据传输正式页面**：新增传输页（如 `transfer_page.dart`），复用已实现的服务层（HttpServer + UDP 发现 + 二维码 `WQA|1.0|{ip}:{port}|{token}`），提供：桌面端展示二维码 / 同网设备列表，连接成功后任一端选择文件传输、进度与结果反馈；**顺带修复「服务层有、页面无」的历史导航 bug**。
- **P0-3 图片转Excel 改造**：
  - ① **移除「选择仪器类型」**（不再依赖 MCGS/E.co 手动选择）。
  - ② **识别表格结构**：从 OCR 结果中识别表头/列与行，产出结构化表格（列名 + 行数据），适配三种仪器列结构（总大肠菌群 MCGS / E.co 三通道 / 总铜，含「未检出」文本与小数）。
  - ③ **框选数据**：识别出表格后，用户可框选需要的数据（具体形态见「待确认问题」）。
  - ④ **自写拍照界面 + 算法**：引入相机预览（详见 P0-4），预览时叠加参考线/边缘提示，引导「拍全表格、表格边缘与屏幕参考线对齐」，参考样例为工业 HMI 蓝色数据查询表格截图（列 = 时间/数据结果/吸光度/数据标识/当前值/空白值）。
- **P0-4 自定义拍照引导**：实现自定义拍照页（评估是否引入 `camera` 插件），在预览上叠加表格参考线框与对齐提示；拍照后仍支持相册多选兜底。
- **P0-5 大肠杆菌计算独立化**：`calculation_page` 增加「拍照 / 导入图片」入口，独立完成 OCR + 数据提取，不再依赖「先在图片转Excel页识别」；计算逻辑（吸光度 `ln(空白/检测)*10000`、空白<检测 反向、拟合 `y=aX+b` 输出 a=B/b=A/R²、E.co 三通道分类）保持不变。
- **P0-6 工具成果归档到工作空间**：所有子工具（图片转Excel、大肠杆菌计算等）执行完成后，提供「创建或导入到工作空间」入口；生成文件可**自定义名字**并保存到指定工作空间。
- **P0-7 工作空间页增强（增删改查 + 字段化命名 + 搜索排序）**：
  - 新增工作空间弹出 **bottom sheet**：必填 `合同编号`、`项目名称`；选填 `项目负责人`、`检测项目`、`其他补充`；按 `项目名称-合同编号-项目负责人-检测项目-其他补充` 拼接命名工作空间（文件夹/名称）。
  - 列表展示；按创建时间**正序/逆序**切换排序；支持**全文模糊搜索**，并可**单独按「合同编号」或「项目名称」**搜索。
  - 支持查看/编辑/删除。
- **P0-8 回收站 + 30 天清理**：删除工作空间进入应用级回收站（`trash/` 目录，非系统回收站）；自动清理 30 天前进入回收站的数据。

### P1（应该完成，提升体验）

- **P1-1 表格结构识别的容错校正**：OCR 识别出的表头/行列支持手动校正（修正列名、增删行、修正单元格）后再进入框选/导出。
- **P1-2 拍照引导的多级反馈**：预览中给出「已对齐/边缘检测到/建议拉远」等轻量状态提示，降低拍斜率。
- **P1-3 工作空间字段与命名预览**：bottom sheet 输入时实时预览拼接后的工作空间名。
- **P1-4 回收站恢复**：回收站内可恢复误删的工作空间（在 30 天窗口内）。

### P2（可延后）

- **P2-1 归档冲突处理**：同名文件保存到工作空间时的重命名/覆盖策略提示。
- **P2-2 工作空间导出/打包**：将工作空间（含文件）打包下载或直接传输到对端。
- **P2-3 数据传输的断点续传/多文件队列**。

## 4. UI 设计要点（增量）

- **导航**：3 个 tab，顺序为「工作空间 | 工具 | 数据传输」；默认落在「工具」；图标建议：工作空间 `folder`、工具 `apps/grid_view`、数据传输 `swap_horiz/cloud_sync`。原「首页」与「设置」入口的去留见待确认问题。
- **工具页**：以工具卡片网格承载「图片转Excel」「大肠杆菌计算」等（不含「数据传输」入口）；「设置」作为次级入口（右上角齿轮或工具页内）承载 OCR 引擎切换等。
- **图片转Excel 页（改造后）**：顶部「拍照 / 相册多选」→ 拍照引导预览（参考线叠加）→ 表格结构识别结果（表头+行，可校正）→ **框选工具**（选择关心的区域/列/行）→ 去重合并 → 导出 Excel → 「保存到工作空间」。
- **大肠杆菌计算页（改造后）**：顶部「拍照 / 导入」→ 独立识别 → 选择空白行/含菌行 → 标液浓度与单位 → 拟合图与 A/B/R² → 「保存到工作空间」。
- **工作空间页**：列表 + 排序切换（创建时间正/逆）+ 搜索框（默认全文模糊，可切换「合同编号 / 项目名称」）；「新增」按钮 → bottom sheet（必填/选填字段 + 拼接命名预览）；条目操作含「编辑 / 删除（进回收站）」。回收站为独立视图或筛选态。
- **数据传输页**：连接方式切换（扫码 / 设备列表）；桌面端展示二维码；连接状态 + 文件选择 + 进度/结果。

## 5. 待确认问题（重点，供架构师与用户澄清）

1. **需求2「框选数据」的精确含义**（三选一或组合）：
   - A. 图片区域裁剪后**重新 OCR**（在图上画框 → 裁出子区域再识别）；
   - B. 识别出表格后**勾选行/列/单元格**（对结构化结果做选择）；
   - C. 两者都要（先图上裁剪、再勾选行列）。
   - → 直接决定数据模型与交互复杂度，需优先确认。
2. **拍照引导的实现边界**：是纯 Flutter 预览叠加参考线（低成本，无边缘检测），还是要做边缘检测/透视提示（需引入 `camera` + 图像处理，复杂度高）？Android 相机权限、`camera` 插件与 `image_picker` 的取舍（引入 `camera` 做自定义预览 vs 继续用系统相机）需确认。
3. **旧「首页」与「设置」页在新 3-tab 中的去留**：「设置」入口放哪（工具页右上角齿轮 / 独立二级入口 / 合并进数据传输页）？「首页」是否彻底移除，还是作为工具页本身？
4. **「保存文件到工作空间」的存储形态**：仍为 JSON 元数据 + 文件目录，还是每个工作空间一个**真实文件夹**？需求5 已暗示「按拼接名命名文件夹」，需明确：
   - 工作空间落盘是否从 `workspaces/<id>.json` 迁移为 `workspaces/<拼接名>/`（内含 `meta.json` + 附件文件）？
   - 现有 `workspace_store.dart`（单 JSON 文件）与 `workspace.dart`（`name/parameter` 字段）如何迁移/兼容（是否需要新增字段 `contractNo/projectName/owner/item/remark`）？
5. **大肠杆菌计算与图片转Excel 的共用手写组件复用方式**：两者都要「拍照/导入 + 表格结构识别 + 框选/校正」，是否抽成共享 widget/service（如统一的 `OcrTableFlow`）？共享边界与是否允许跨页面传递已识别数据需明确。
6. **回收站方案确认**：系统回收站不适用于应用文档目录，方案为**应用级 `trash/` 目录 + 30 天自动清理**，是否可接受？删除工作空间是否连同其下文件一起移入 trash，还是仅移元数据？
7. **「创建或导入到工作空间」的语义**：「创建」= 新建一个工作空间再写入；「导入」= 写入已存在的工作空间；两者是否都要，还是统一为「选择/新建工作空间」的一个流程？
8. **工作空间命名的空字段处理**：`项目负责人/检测项目/其他补充` 选填为空时，拼接名中是否保留占位（如 `-`、`无`）还是省略该段？是否允许用户最终手动改名？
