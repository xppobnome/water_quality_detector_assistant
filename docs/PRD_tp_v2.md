### 1.3 术语统一

- 「工作空间」（不再用「工作区间」「工作区」）。
- 「数据集」= 一次导入产生的一组行。
- 「行」= 一条测量记录（一行 = 一个时间点的 6 列数据）。
- 「浓度档位」= 国标规定的浓度水平（10% / 20% / 50% / 80% / 0.1 mg/L / 0.02 mg/L）。
- 「分段」= 多段试验（电压/浊度/温度/记忆效应）中某一段条件对应的若干行。

## 2. 数据口径与浓度档位定义（一切判定的基础）

### 2.1 现场数据列（固定 6 列，OCR 结果必须映射到这 6 列）

| 列 | 语义 | 参与国标计算 | 说明 |
| --- | --- | --- | --- |
| 时间 | 测量时刻 | **是**（排序 + 24h 连续性校验） | 格式 `2026-11-05 22:00:00`，每小时 1 条，一天 24 条 |
| 数据结果 | 测定浓度（mg/L） | **是**（核心量，下文记作 r） | 保留 3 位小数参与计算与展示 |
| 吸光度 | 过程量 | 否 | 仅展示 |
| 数据标识 | 有效性（`N`=正常，其他=异常） | **是**（决定是否默认参与计算） | 异常行默认不勾选，灰显 |
| 当前值 | 过程量 | 否 | 仅展示 |
| 空白值 | 过程量 | 否 | 仅展示 |

示例行：`2026-11-05 22:00:00 | 0.8006 | 0.4308 | N | 2424.500 | 3784.100`

### 2.2 量程与浓度档位（**数字不得修改**）

| 量程 | 范围 | 结果保留 | 上限值 |
| --- | --- | --- | --- |
| 基本量程 basic | 0.02 ~ 4 mg/L | 3 位小数 | 4 mg/L |
| 扩展量程 extended | 4 ~ 50 mg/L | 3 位小数 | 50 mg/L |

| 档位键 | 基本量程标称值 | 扩展量程标称值 | 用途 |
| --- | --- | --- | --- |
| L10（10%） | 0.400 mg/L | —（未规定，不提供） | 示值误差、浊度影响（10%=0.4） |
| L20（20%） | 0.800 mg/L | — | 示值误差、重复性、记忆效应低浓度段 |
| L50（50%） | 2.000 mg/L | 25.000 mg/L | 示值误差 |
| L80（80%） | 3.200 mg/L | 40.000 mg/L | 示值误差、重复性、24h 高漂移、记忆效应高浓度段、电压、温度 |
| L0_1 | 0.100 mg/L（约 0.1） | — | 24h 低浓度漂移 |
| L0_02 | 0.020 mg/L | — | 定量下限 |

### 2.3 自动归类规则（S7 浓度分类）

1. 每行的「数据结果」r 与各档位标称值 X 比较，相对偏差 `|r − X| / X ≤ 10%` 即判为落入该档（**档位容差 10%**，单一常量，便于后续调整）。
   - 例：0.8 档容差 ±0.080 → 0.721~0.879 归入 L20；3.2 档容差 ±0.320 → 2.881~3.519 归入 L80。
2. 若一行只落入 1 个档 → 直接归类；落入 0 个档 → 标为「未归类（离群）」，灰显、不参与任何档位判定，并在 S7 底部汇总「未归类 N 条」。
3. 档位之间标称值差距 ≥ 100%，10% 容差下不存在跨档重叠，无需多档仲裁。
4. 档位可由用户手动改写（S6 行选择页每行「档位」下拉），手动值优先于自动值，UI 上手动值右侧带小锁图标。

### 2.4 24h 连续性校验规则

- 判定「满足 24h 连续」需同时成立：行数 ≥ 24；相邻两行时间间隔在 40 ~ 80 min 之间（允许少量漏测）；首末行时间跨 ≥ 23 h。
- 不满足时的提示文案见 S7-⑤。

## 3. 状态机

### 3.1 工作空间状态

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `draft` 草稿 | 仅存在内存/临时文件，未落盘为正式工作空间 | S1 点草稿卡片；或 S2 创建时勾选「先存草稿」 |
| `saved` 已保存 | 已落盘（`workspaces/<拼接名>/`），可再次编辑 | 草稿点「保存」；S2 点「创建」 |
| `computing` 计算中 | 已选数据集与验证项，正在 / 已完成计算 | S7 点「开始计算」 |
| `exported` 已导出 | 至少导出过一次 Excel，`lastExportedAt` 非空 | S9 导出成功 |

### 3.2 迁移与允许的操作

| 当前状态 | 事件 | 结果状态 | 允许的操作 |
| --- | --- | --- | --- |
| draft | 保存 | saved | 编辑字段 / 导入数据 / 计算 / 导出 |
| draft | 不保存（S10 选「不保存」） | 销毁 | — |
| saved | 修改字段或数据 | saved（`dirty = true`） | 全部 |
| saved | 开始计算且校验通过 | computing | 重算 / 改选行 / 导出 |
| computing | 导出成功 | exported | 重算（回到 computing）/ 再次导出 / 归档 |
| exported | 再次编辑数据 | saved（`dirty = true`，`results` 标记「已过期」） | 全部 |

### 3.3 未保存（dirty）判定

满足任一即 `dirty = true`：

- 草稿态下任意字段/数据被写入；
- 已保存态下 表单字段、数据集行、选行集合、验证项选择、量程、分段绑定、手工输入的维护周期 任一项变化；
- 计算结果产生后尚未导出（`dirty = true` 且提示语为「结果未导出」）。

`dirty = false` 的时机：点「保存」成功、导出 Excel 成功（仅清除「结果未导出」这一项）。

### ⑤ 校验与边界

### ⑤ 校验与边界

- **不能进入 S7 的情况**：未选任何行（S6 已拦截）。
- 档位归类的「需/实」计算：`需` = 已选验证项在该档位的国家标准条数之和（如同时选「示值误差」与「重复性」，L20 档需 6+6=12）；`实` = 选中行归入该档的条数。
- 同一行可被多个验证项复用（例如 L80 的 6 条既可用于示值误差也可用于重复性），但**同一行不能同时归属两个不同档位**。
- 「过多」时默认取时间升序前 N 条。UI 上必须明示「按时间取前 6 次」，并在 S8 中列出被采用的具体时间点，保证可审计。
- 24h 校验不通过时，该两项显示「无法判定」而非「不合格」。
- 分段绑定段数固定（电压 3 / 浊度 3 / 温度 5 / 记忆效应 4 段：80%×3 不考核 + 0.8×7 + 3.2×7 → 实际按 3 段展示：`80% 预冲（3 条，不考核）`、`0.8 mg/L（7 条）`、`3.2 mg/L（7 条）`）。
- 数值边界：mg/L 数值允许 0~50；超过 50 标红 `超出扩展量程上限 50 mg/L`。

**示例 A（示值误差）逐字文案**（工程师可直接作为模板字符串）：

```
第 1 步  分档取值
  公式：—
  代入：10%=0.400、20%=0.800、50%=2.000、80%=3.200 mg/L
  结果：4 档 × 6 次 = 24 条数据
  说明：按「数据结果」自动归入最接近的浓度档位，档位容差 ±10%。

第 2 步  计算 20% 档 6 次测定的平均值
  公式：r̄ = (r₁ + r₂ + … + r₆) / 6
  代入：(0.8062 + 0.7985 + 0.8103 + 0.7971 + 0.8034 + 0.8008) / 6
  结果：= 4.8163 / 6 = 0.803 mg/L
  说明：20% 档 6 次测定的算术平均值，保留 3 位小数参与下一步。

第 3 步  计算 20% 档相对误差
  公式：δ = (r̄ − X_s) / X_s × 100%
  代入：(0.80272 − 0.800) / 0.800 × 100%
  结果：= +0.34%
  说明：X_s 为该档标液标准值；正号表示示值偏高。

第 4 步  取 4 个浓度档位中最大相对误差
  公式：δ_max = max(|δ_i|)，i = 10% / 20% / 50% / 80%
  代入：|−1.12%|、|+0.34%|、|+0.61%|、|−2.05%|
  结果：δ_max = −2.05%（80% 档，3.200 mg/L）
  说明：取绝对值最大的一档作为该验证项的最终结果。

第 5 步  判定
  公式：|δ_max| ≤ 5% 判为合格
  代入：|−2.05%| = 2.05%
  结果：2.05% ≤ 5% → 合格
  说明：最大误差出现在 80% 档，仍低于允许上限 5%。
```

**示例 B（24h 低浓度漂移）逐字文案**：

```
第 1 步  校验 24h 连续性
  公式：—
  代入：≥ 24 条、相邻间隔 40~80 min、首末跨度 ≥ 23 h
  结果：24 条；间隔 60 min；跨度 23h00m → 满足连续 24h
  说明：任一条件不满足时本项判为「无法判定」，不判「不合格」。

第 2 步  计算初始均值 r̄₀（最初 3 次）
  公式：r̄₀ = (r₁ + r₂ + r₃) / 3
  代入：(0.1002 + 0.0995 + 0.1008) / 3
  结果：= 0.3005 / 3 = 0.1002 mg/L
  说明：以试验开始的最初 3 次测定均值作为漂移基准。

第 3 步  逐条计算与基准的绝对偏差
  公式：dᵢ = |rᵢ − r̄₀|
  代入：
    2026-11-02 12:00  r=0.0958 → d = |0.0958 − 0.10017| = 0.004 mg/L
    2026-11-02 15:00  r=0.1070 → d = |0.1070 − 0.10017| = 0.007 mg/L
    2026-11-02 23:00  r=0.1039 → d = |0.1039 − 0.10017| = 0.004 mg/L
    （其余 21 条见「全部 24 行偏差明细」）
  结果：偏差最大为 0.007 mg/L（2026-11-02 15:00）
  说明：正值表示测得浓度高于基准，负值表示低于基准，判定只看绝对值。

第 4 步  取最大偏差 Δ_max
  公式：Δ_max = max(dᵢ)，i = 1…24
  代入：max(0.0002, 0.0007, …, 0.007, …, 0.0037)
  结果：Δ_max = 0.007 mg/L
  说明：24h 内偏离基准最远的时刻即为漂移量。

第 5 步  判定
  公式：Δ_max ≤ 0.01 mg/L 判为合格
  代入：0.007 mg/L ≤ 0.01 mg/L
  结果：合格
  说明：实测漂移 0.007 mg/L，为允许值的 70%，余量充足。
```

**示例 C（定量下限，紧凑版）**：

```
第 1 步  列出 0.020 mg/L 溶液 7 次测定值
  结果：0.0192、0.0205、0.0211、0.0188、0.0202、0.0196、0.0209
第 2 步  计算平均值
  公式：r̄ = Σrᵢ / n
  代入：(0.0192+0.0205+0.0211+0.0188+0.0202+0.0196+0.0209) / 7
  结果：= 0.1403 / 7 = 0.0200 mg/L
第 3 步  计算样本标准差 S
  公式：S = √[ Σ(rᵢ − r̄)² / (n − 1) ]
  代入：√(4.5368×10⁻⁶ / 6)
  结果：= √7.5613×10⁻⁷ = 0.00087 mg/L
第 4 步  计算定量下限
  公式：LOQ = 10S
  代入：10 × 0.00087
  结果：= 0.0087 mg/L
第 5 步  判定定量下限
  公式：LOQ ≤ 0.02 mg/L 判为合格
  结果：0.0087 ≤ 0.02 → 合格
第 6 步  判定该浓度示值误差
  公式：δ = (r̄ − X_s) / X_s × 100%
  代入：(0.02004 − 0.020) / 0.020 × 100%
  结果：= +0.22%，|δ| ≤ 30% → 合格
```

| 返回 S7 | 顶部返回键；有计算结果时 S7 显示 `已计算，可查看汇总` |
| 页面留存 | 计算结果写入工作空间 `results`（与现有 `CalcResult` 对齐，需要新增 `steps` 快照，见 §14） |

### ⑤ 校验与边界

- 步骤确定性：同样的输入必须得到同样的输出（禁止随机/时间相关逻辑入公式）。
- 数字格式：mg/L 3 位小数；% 2 位小数；h 整数；算术中间量至少保留 5 位有效数字再四舍五入到展示精度（示例 A 中 0.80272 是未截断值）。
- 「无法判定」不参与合格率统计（S9 单独列出）。
- 若某档位数据不足，仅该档位缺失 → 整项「无法判定」，不允许用其他档位的结果替代。
- 「过多」自动截取时，必须在第 1 步或卡内行清单中明确写出被采用的时间区间，例如 `说明：20% 档共 12 条，按时间取前 6 条（11-01 22:00 ~ 11-02 03:00）。`
- 极值保护：分母为 0（标液值 0、均值 0）→ 该项「无法判定」，原因 `计算中出现除零（X_s = 0）`。
- 数值溢出/NaN → `无法判定` + 原因 `数据异常，请检查是否存在非数字或空值`。

| 5 | 24h 高浓度漂移 | 5.5.5 | 80% 上限值 = **3.2 mg/L**（扩展 40 mg/L） | **连续 24h 共 24 条** | 同第 4 项；`Δ%=Δ_max/上限值×100%`（上限值：基本 4、扩展 50） | 基本 **≤1%**；扩展 **≤5%** | 同时展示 `Δ_max (mg/L)` 与 `Δ%`，判定用 `Δ%`；分母明确写出「上限值 4 mg/L」 |
| 6 | 记忆效应 | 5.5.6 | 80% (3.2) 与 20% (0.8) 交替 | 80% **3 次（不考核）** → 20% **7 次** → 80% **7 次** | 高→低 `δ₁=(r̄_low−0.800)/0.800×100%`；低→高 `δ₂=(r̄_high−3.200)/3.200×100%` | 80%→20% **±10%**；20%→80% **±5%** | 三段卡片（预冲段灰显标 `不考核`）+ 两个判定行分别给徽标；两个都合格才整项合格 |
| 7 | 电压影响 | 5.5.7 | 80% = 3.2 mg/L | 220V / 242V / 198V **各 3 次**（共 9 次） | 各段均值 → 基线 `X̄₂₂₀`；`δ=(X̄_影响−X̄₂₂₀)/X̄₂₂₀×100%` | **±5%** | 三段均值表 + 两个 δ；220V 段标 `基线` 徽标；`δ_max` 超限标红 |
| 8 | 浊度影响 | 5.5.8 | 10% = 0.4 mg/L | 无浊度 / 100 NTU / 300 NTU **各 3 次**（共 9 次） | 基线 = 无浊度段均值；`δ=(X̄_影响−X̄_基线)/X̄_基线×100%` | **±15%** | 同上；基线段标 `基线` |

| 10 | 实际样品比对 | 5.5.10 | **5 种实际样品** | 每种仪器 **≥10 次** | `x̄ᵢ` 与实验室均值 `cᵢ` 比较；**浓度分类**：`cᵢ<0.4` → `\|x̄ᵢ−cᵢ\| ≤ 0.04 mg/L`；`cᵢ≥0.4` → `\|x̄ᵢ−cᵢ\|/cᵢ×100% ≤ 10%` | 绝对 **≤0.04 mg/L** / 相对 **≤10%** | 5 行表格，每行显示 `cᵢ`、`x̄ᵢ`、`判定方式（绝对/相对）`、差值、结论；`cᵢ` 跨 0.4 时在行内显式标 `浓度分界` |
| 11 | 最小维护周期 | 5.5.11 | — | 1 个实测值（用户输入） | `t`（小时） | **≥168 h** | 输入框 + 单条判定行 `t = 168 h ≥ 168 h → 合格`；未填 → `无法判定` |
| 12 | 数据有效率 | 5.5.12 | 全部参与行 | 全部行 | `有效率 = 有效行数 / 总行数 ×100%`（有效 = 数据标识 `N`） | **≥90%** | 分子/分母写明（`有效 22 / 总 24 = 91.7%`），并列出被判为无效的行数与标识分布 |
| 13 | 一致性偏差 | 5.5.13 | 3 台仪器 × 168 个时段 | 3 组数据源，按时间对齐 | `\|a−b\|/((a+b)/2)×100%`，取全部时段全部组合最大值 | **≤10%** | 三源选择 + 对齐时段数 + 最大偏差出现的时段与两台仪器编号 |

**判定呈现统一规则**：`指标值 ≤ 限值`（越大越差类）→ 合格；`指标值 ≥ 限值`（越大越好类，如有效率 90%、维护周期 168h）→ 合格；数据不足 → 无法判定（灰色，不计入合格率）。

## 14. 对数据模型的增量要求（供架构师 / 工程师参考，本文不写代码）

| 对象 | 需新增/调整 | 说明 |
| --- | --- | --- |
| `Measurement` | `dataFlag`（数据标识，如 `N`）、`absorbance`、`currentValue`、`blankValue`、`levelKey`（自动归类结果）、`levelManual`（bool 是否手动指定） | 现有仅有 `values{'value'}` 与 `rawText`，需要承载 6 列语义 |
| `Workspace` | `itemId`（检测项目 code：`cod`/`tn`/`tp`/`nh3n`）、`isDraft`、`dirty`、`lastComputedAt`、`lastExportedAt`、`stages`（分段绑定）、`manualInputs`（维护周期、5 个实验室均值） | 现有 `parameter` 承担「标准 id」，`item` 是自由文本，需要区分「检测项目（业务）」与「标准（计算）」 |
| `CalcResult` | `steps: List<CalcStep>`、`levelResults`、`unableReason` | `CalcStep{index, title, formula, substitution, result, note}`，S8 直接渲染 |
| 新增 `ValidationSpec` | 13 项的 `clauseNo`、`levels`、`requiredCount`、`formula`、`limits`、`clauseText` | 从 `standard_definitions.dart` 扩展，UI 读取不硬编码 |
| 新增 `DraftStore` | 单草稿持久化（`drafts/current.json`），防抖 2s / 30s 兜底 | 支持强杀恢复 |
| 导出 | `ExcelExportService` 增加 4 Sheet 生成（结果汇总 / 数据集 / 计算过程 / 标准依据） | Sheet 3 需要 steps 快照 |

**现有实现的已知偏差（必须在实现前修正，否则计算不合规）**：

1. `standard_definitions.dart` 中 `indication_error` 的 `basic` 限值为 `30%`，与标准要求的 **±5%** 不一致（30% 仅适用于定量下限浓度点的示值误差）。
2. `verification_service.dart` 的 24h 漂移使用 `|末值−初值|` 与「以初值为基准的百分比」，标准要求 **r̄₀ = 最初 3 次均值**，低浓度漂移用**绝对量 ≤0.01 mg/L**。
3. `loq` 使用「绝对偏差 0.04 mg/L」，标准要求 **LOQ = 10S ≤ 0.02 mg/L** + 该浓度示值误差 ±30%。
4. 记忆效应仅有 1 个限值（10%），标准要求 **80%→20% ±10% 与 20%→80% ±5%** 两个判定。
5. 缺少「实际样品比对」「最小维护周期（手输）」「数据有效率（由数据标识统计）」的独立实现路径。

## 16. 关键界面验收清单（QA 可直接当用例标题）

4. 导入 Excel 缺「时间」列时报错并中止，不产生半截数据。

9. 示值误差卡展示 5 个步骤，公式、代入（真实数字）、结果、说明齐全；条款原文可折叠展开。

12. 导出 Excel 含 4 个 Sheet，Sheet 2 行数与界面「已选 N 行」一致，Sheet 3 含每项每步的公式与代入。
13. 数据修改后状态显示「结果已过期」，导出后变「已导出」。

| # | 问题 | 影响 | 我的建议 |
| --- | --- | --- | --- |
| Q1 | **条款号与原文**：PDF 第 5.5 章的精确条款编号（5.5.1~5.5.13 为占位）与原文摘录尚未逐条校对 | S8 折叠区、导出 Sheet 4 的「标准依据」 | 由用户提供 PDF 或确认编号后，一次性写入 `ValidationSpec`；UI 不做硬编码 |

| Q4 | **记忆效应两条限值的对应**：本设计 80%→20% 用 ±10%、20%→80% 用 ±5% | 判定方向错误风险 | 需对照 PDF 5.5.6 原文确认；若不成立则改为「均按 ±10%」 |
| Q5 | **温度 20℃ 三段**：基线取第 1 段还是三段均值 | 影响 δ 数值 | 建议基线 = 第 1 段 20℃，第 3/5 段仅作回程一致性展示（不判定） |
| Q6 | **浓度档位容差 ±10%**：现场数据不会正好等于 0.400/0.800 | 归类正确率 | 建议保留 ±10% 并可覆盖；若现场偏差更大可调至 ±15% |
| Q7 | **「过多」数据取哪 6 条**：按时间前 6 vs 最接近标称值 6 条 | 结果可复现性与合规解释 | 建议默认按时间升序（可审计），并在行清单中标注被舍去行 |
| Q8 | **一致性偏差的数据组织**：3 台仪器数据如何入库（3 个数据集？3 个工作空间？） | S7 第 13 项交互 | 建议 3 个数据源下拉（可为同一或其他工作空间的数据集），按时间对齐取交集 |

**最需要用户拍板的 3 个设计取舍**：

1. **浓度档位：自动归类 vs 手动指定** —— 我选「自动归类（±10% 容差）+ 可逐行手动覆盖」。理由：现场每小时 1 条、一次几百行，纯手动不可操作；纯自动又无法处理仪器偏移，故留覆盖。
2. **「数据过多」时取哪几条** —— 我选「按时间升序取前 N 条」并全程留痕，而不是「取最接近标称值的 N 条」。理由：审核场景下「可复现、可解释」比「数值最好看」重要。
3. **24h 漂移的基准与比较方式** —— 我选「r̄₀ = 最初 3 次均值，逐条比较取最大绝对偏差」，并显式写出被采用的口径。理由：符合任务书要求（r̄₀ 定义），同时避免滑窗引入不可解释的中间量。
