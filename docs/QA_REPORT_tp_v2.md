## 2. P0（合规性错误，必须修）

### P0-1　记忆效应未排除「前置 3 次 80%」，默认流程必然误算，且会产生假「不合格」

- **文件:行号**
  - `lib/services/gb_calculator.dart:881-891`（`_memory` 取 `segments.first.samples.take(7)`，`r1 = xs.first`，无偏移）
  - `lib/services/gb_calculator.dart:278-280`（`autoBindSequential` **最后一段吃掉全部剩余**，单分段项因此拿到全部 17 行）
  - `lib/pages/verification/calc_setup_page.dart:86-93`（默认全选所有有效行）、`:192-202`（`_autoBind` 仅"顺序切分"）
- **现象（实测）**：标准试验为 `3×80%（不考核）+ 7×20% + 7×80% = 17 行`。用户按常规把 17 行全部选中后：
  - 「记忆效应（80%→20%）」实际取到的是 `3.200, 3.200, 3.200, 0.800, 0.800, 0.800, 0.800`；
  - 计算得 `r₁=3.2000`、后 6 次均值 1.6000 → **RE = +100.00% → 判不合格**（实测输出见 §5 用例 15c）。
  - 「记忆效应（20%→80%）」同样错位。
- **标准依据**：HJ 103—2026 **5.5.1.6**：「连续测量 3 次…80% 的标准溶液后（**测定结果不作考核**），再依次测量…20% 7 次，…80% 7 次。分别计算每种标准溶液**第 1 次**测定值与**后 6 次**测定值的平均值之间的误差」。
- **期望 vs 实际**
  - 期望：80%→20% 项使用数据集的第 4~10 条（7×20%）；20%→80% 项使用第 11~17 条；第 1~3 条不参与任何计算。
  - 实际：两项都取「前 7 条」，第 1~3 条（80%）被当作考核数据，结论为「不合格」，RE 100%（正确值应 ≈0%）。
- **风险等级**：高——这是**标准操作流程（默认全选）下的必然错误**，且错误方向是"把合格仪器判为不合格"。
- **建议修法（由 Engineer 实施）**：`segmentSpecs('memory_*')` 增加 `skipPrefix: 3`/`offset` 字段；`autoBindSequential` 对记忆效应先从第 4 条开始取 7 条；或在 `_memory` 内按 `target` 浓度过滤（20% 项只取 value≈0.8 的 7 条，80% 项取切换后 7 条）。同时 `checkSegments` 需能提示"已自动跳过前置 3 次 80%（不考核）"。

### P0-2　数据条数不足时仍出具「合格／不合格」判定（规范要求「无法判定」）

- **文件:行号**
  - `lib/services/gb_calculator.dart:420`（示值误差 `used.length < 2` 即计算，标准要求每档 6 条）
  - `:519`（LOQ `< 2` 即计算，要求 7 条）
  - `:619`（重复性 `< 2`，要求 6 条）
  - `:714` / `:798`（漂移 `< 4` 即计算，要求 24 条）
  - `:884`（记忆效应 `< 3` 即计算，要求 7 条）
- **现象（实测）**：示值误差 4 档每档只给 2 条（2/6）→ 输出 **`指标 0.13 %`、结论「合格」**，仅 `dataNote` 有文字提示（§5 用例 15b）。LOQ 给 2 条、重复性给 2 条同样会出结论。
- **标准依据**：`docs/GB_HJ103_TP_SPEC.md` §5「**无法判定**：数据不足 / 分母为 0 / 数据缺失 → 结论 = "无法判定"，**不参与合格统计**」；§4.1「条数：基本 4×6 = 24」、§4.2「7」、§4.3「2×6=12」。
- **期望 vs 实际**：期望结论 `notApplicable`（页面与 Excel 的"判定"列显示"无法判定"）；实际显示"合格/不合格"，并计入 `passCount`/`failCount` 与总体结论（`gb_verify.dart:343-347`）。
- **加重情节**：导出的《结果汇总》Sheet 的"判定"列写「合格」，虽"备注"列带 `dataNote`，但**对外报告的第一结论是错误的**。
- **建议修法**：为 `GbSegmentSpec` 增加 `strict`（默认 true）；任一必需分段 `n < required` 时直接返回 `notApplicable`（保留 `dataNote` 说明缺几条）；确需"参考计算"时用单独字段 `reference: true`，且导出判定列写「参考（数据不足）」。

## 10.3 本轮新发现（回归 / 缺口）

### N1（P1，回归）多段验证项的「总条数超出」被静默丢弃

- 对比：修复前最后一段会"吃掉剩余行"并触发「多出 N 条」提示，因此这是**旧问题在新实现下的重新出现**（P1-2 的同类）。

### N2（P2）记忆效应多余的高浓度行被静默并入「不考核」段

- 实测：24 条（7 条多余 80% + 3 前置 + 7×20% + 7×80%）→ `pre:10, low:7`，`checkSegments` 返回空串；7 条多余的 80% 行无人知晓。

### N3（P2）`GbSegmentSpec.min` 成为死字段，漂移 4~23 条口径与规范 §4.4 不一致

## 11.3 遗留观察（不阻断交付，均为已记录项）

1. **记忆效应「末尾 7 条」启发式对行序敏感**（上一轮 §10.6-3 已记录，本轮补实测）：同样 19 条数据，多余 2 条高浓度放在**前置段** → RE=0.015623%；追加在**末尾** → 「末尾 7 条」窗口移位，RE=0.008853%（r₁ 变成 3.2006）。两种都合规（都在 ±5% 内），但判定用的具体行不同；建议 UI 在记忆项上提示「请确保数据按 3×80% → 7×20% → 7×80% 顺序导入」，或让用户用「手动绑定」锁定这两段。
2. **一致性偏差按条数顺序切分**：3 台仪器需按 168 条/台连续存放；若某台多录了行（如 520 条/台），切分点会错位（本次 1560 条 → `168,168,1224`，第 3 段混入第 1/2 台的剩余行）。已有「多出 1056 条」提示 + 手动绑定可纠正，但提示只讲条数、不讲"分段边界可能错位"。建议在该项提示中补一句「请确认三台仪器的数据是否为连续的三段」。
3. **历史计算列表文案**：副标题只显示「合格 X / 不合格 Y（/ 无法判定 Z）」，而徽章用的是覆盖度感知后的 `overall`。当「只算 1 项且通过」时会显示「合格 1 / 不合格 0」+ 徽章「无法判定」。语义正确但易误读，建议副标题追加「未计算 N 项」（`missingItemCount` 已可用）。
4. **N4 的提示优先级**：当同时存在「无法判定项」与「未计算项」时，`overallHint` 只输出 naCount 分支，未提「尚有 Z 项未计算」。建议合并成一句（信息更完整）。
